# 画面設計案

## 状態・共通設計

2026-09-22 作成。[要件](requirements.md)を基にした 4 画面の提案であり、UI・アクセシビリティの実装 / テストは未実施です。[API](api.md)の API-01～API-12、[DB](database.md)のコード・型を使い、[横断対応表](design-review.md)で FR / AC を追跡します。

社員と IT担当者で一覧・詳細画面を共用します。ボタンの表示は操作を案内するためのもので、認可は API の認証・Policy・閲覧スコープ・DB transaction が毎回保証します。ログイン本人は API-04 で取得し、ブラウザーの書換可能な role をサーバーの認可根拠にしません。

| ID | URL（SPA） | 利用可能な役割 | 主な API |
| --- | --- | --- | --- |
| SCR-01 | /login | 未認証、社員、IT担当者 | API-01・API-02・API-04 |
| SCR-02 | /requests?page=1 | 社員・IT担当者 | API-04・API-05、共通 API-03 |
| SCR-03 | /requests/new | 社員 | API-04・API-06、共通 API-03 |
| SCR-04 | /requests/{request_id}?comment_page=1 | 社員は自分、IT担当者は全件 | API-04・API-07～API-12、共通 API-03 |

`/requests/new` を ID ルートより先に解決します。SPA のルートと `/api/*` のルートを混同せず、GET /login は画面、POST /login は認証 API です。page / comment_page は正の整数、ID は数字文字列。画面から API へは comment_page を `page` に変換します。URL に本文・メール・資格情報を入れません。未提供画面は安全な 404 表示にします。

全画面に「**架空データ専用の期間限定デモです。実在の個人情報、パスワード、APIキー、社内の機密情報を入力しないでください。**」と、事前案内した公開終了日時（JST）を表示します。認証情報の配布は別経路で行い、画面に共通パスワードを掲載しません。

## 共通状態と操作

| 状態 | 表示・操作 |
| --- | --- |
| 初回読込 | API-04 完了まで保護本文・操作を出さず「読み込み中」。戻る操作等の GET は実行可能だが stale な本文を別利用者へ見せない |
| 入力検証 | 必須・上限・型の補助検証。422 の field error を各ラベルに対応付け、フォーム先頭の要約へ focus。サーバー検証が最終判断 |
| 401 / セッション期限 | 本文・選択・下書き・本人情報のメモリーを消去し SCR-01 へ。「セッションが終了しました」。パスワードは再入力。安全な内部戻り先の path だけをメモリーに保持 |
| 419 | 自動再送せずフォームを消去して SCR-01 へ。API-01 から初期化し再ログイン。ログイン済みだった可能性もあるため「認証状態を確認してください」と案内 |
| 403 | 「この操作は利用できません」。保護情報がないエラー領域を表示し、操作を無効化、一覧へ戻る導線。API-04 / 対象 GET の再確認前にフォームを再有効化しない |
| 404 | 不存在と閲覧不可を同じ「対象が見つかりません」。ID・所有者等のヒントを足さず、一覧へのリンクだけ表示 |
| 409 | 最新詳細・候補・コメントを再取得して変更を通知。担当・状態の選択はリセット。コメント下書きは認証と閲覧権が維持される間だけメモリーで保持し、完了なら送信不可として破棄ボタンを表示 |
| 429 | ログインフォームで Retry-After に従い待機表示、送信不可。自動再送せず時間後に手動送信可。パスワード欄は消去 |
| GET 通信エラー | 古いデータなら「更新できていません」と明示して更新操作を止める。読込の再試行ボタン。JSON でない 5xx でも HTML をそのまま描画しない |
| 更新結果不明 | 「処理結果を確認できません。再送せず一覧・詳細を確認してください」。GET で確認できるまで同じ操作は無効。確認できなければ作成者へ相談。登録・コメントに自動重複排除はない旨を示す |
| 送信中 | フォームと関連更新ボタンを無効化、送信中表示。Enter / 二重クリックも同一 in-flight guard で防ぐ。画面遷移による通信中断を rollback の証拠にしない |
| ログアウト | 共通ヘッダーから API-03。成功時に全メモリーを消去し SCR-01 へ。失敗時も保護表示を隠すが、サーバー失効完了とは表示しない。API-04 で確認して明示的に再操作 |

保護画面へ直接移動するときも API-04 と対象 API を検査します。ログイン後の戻り先は同一サイトの上記ルートに限定し、外部 URL や二重 slash を受け付けません。別アカウントで再ログインしたら全 cache / draft を破棄し、元の ID は改めてサーバーで認可します。ブラウザーの戻る・タブ復帰でも保護情報を表示する前に認証確認・再取得を行う案です。

ボタンは native button、リンクは link とし、Tab 順を視覚順に揃えます。入力に可視 label、必須・上限説明、`aria-describedby`・`aria-invalid` を付け、placeholder だけをラベルにしません。読込は aria-busy、完了通知は aria-live、失敗要約は alert とフォーカスで通知。状態は色だけでなく文字を併記します。ページ遷移後は主見出しへ、エラーでは要約から該当入力へ移動できるようにします。

## SCR-01 ログイン

```text
社内IT依頼・改善管理サービス
架空データ専用 / 公開終了日時 / 入力禁止の案内
ログイン
[エラー要約・待機時間]
メールアドレス [________________]
パスワード     [________________]
[ログイン]  [読込を再試行（失敗時）]
```

email（最大254）と password（1～128、加工しない）を入力。メール形式・前後空白除去・小文字化は API と同じ。`autocomplete=username` / `current-password` を用い、remember me・新規登録・再発行・役割選択は出しません。初期化中は送信を無効にし API-01 を取得します。API-02 成功後 API-04 で本人を確認して SCR-02 または許可された戻り先へ移動。既にログイン済みなら API-04 成功後一覧へ移動します。

不存在・停止・誤パスワードは共通メッセージ。422 は項目別、429 は待機表示、401 / 419 は認証を取り直しパスワードを消去します。通信失敗ではログイン結果不明として API-04 で確認し、勝手に API-02 を再送しません。0 件・業務競合・完了状態はこの画面では該当しません。

## SCR-02 依頼一覧

```text
サービス名 / 本人表示名・役割 / [ログアウト]
架空データ専用の案内
依頼一覧（社員：自分の依頼 / IT：すべての依頼）
[依頼を登録（社員のみ）] [再読込]
ID | タイトル（詳細リンク） | 種別 | 依頼者 | 担当者 | 状態 | 作成日時
... 20 件まで ...
対象件数 / 現在ページ [前へ] [次へ]
```

API-05 を page ごとに呼び、created_at DESC, id DESC を表示順のまま使います。ID は文字列、未割当は「未割当」、日時は JST、英字コードは日本語ラベル。version は非表示で保持しても、一覧から直接変更はしません。入力はページ移動だけで、検索・絞り込み・並べ替えを追加しません。

社員の 0 件は「依頼はまだありません」と登録リンク、IT の 0 件は同じ案内だけ。範囲外ページの 0 件は先頭ページへのリンクを出し、全件 0 件と区別します。本人の件数だけを表示し、社員へ全社件数を返しません。読込中は一覧領域を busy にし、通信エラーは再読込。完了依頼も詳細リンクから参照可能です。登録ボタン → SCR-03、行リンク → SCR-04。キーボードでは表の全行をクリック領域にせず明確なタイトルリンクを使います。

## SCR-03 依頼登録

```text
共通ヘッダー / 架空データ専用・機密情報入力禁止
新しい依頼
[エラー要約]
タイトル（必須・100文字） [________________]
種別（必須） [問い合わせ / 不具合 / 改善要望]
内容（必須・5000文字） [複数行________________]
[登録する] [一覧へ戻る]
```

社員のみ。IT の直接 URL アクセスは権限不足表示とし、API-06 も必ず 403 を返す設計です。入力は title / category / body だけ。担当・状態・依頼者・日時は入力させません。文字数はコードポイントで表示し、日本語・絵文字でサーバーとの一致を検証します。タイトルは改行不可、内容は LF 改行を許可。

送信前・API-06 実行中は guard を設け、201 の返却 ID で SCR-04 に移動し、入力を破棄します。422 は入力を保持、401 / 419 は共通規則で消去。409 は通常発生しないため成功扱いせず共通案内。通信失敗は登録結果不明とし、入力は同じログイン中のメモリーに残して本人一覧の再取得で確認します。結果確認まで再登録不可。未送信入力がある通常の画面離脱では破棄確認を案内しますが、期限切れ時は保護表示の消去を優先します。0 件・完了後の操作は該当しません。

## SCR-04 依頼詳細

```text
共通ヘッダー / 架空データ専用の案内 / [一覧へ戻る]
依頼 #ID  タイトル   [再読込]
種別 / 依頼者 / 担当者 / 状態 / 作成日時 / 更新日時
内容（プレーンテキスト）
IT・未完了だけ：
  担当候補 [候補ラジオ一覧・前へ/次へ] [担当を変更]
  未対応だけ [担当を解除]
  状態 [次に可能な状態] [状態を変更]
コメント（古い順・20件） 投稿者 / 日時 / 本文
[前へ] [次へ] / ページ・件数
未完了：コメント（2000文字） [複数行] [投稿する]
完了：完了した依頼です。追加相談は新しい依頼で登録してください。
```

API-07 の認可成功後 API-11 を取得し、ITかつ未完了だけ API-08 を取得します。別々の取得の間に状態が変わる可能性を前提に、変更時はサーバーで再検査します。担当候補に email・停止状態等を表示せず、id / display_name のみ。候補は native radio とページ移動で選び、選択した ID と表示名を別欄に保持します。現在の担当が候補に出ない場合でも詳細の担当表示を残し、新たな有効候補への変更を促します。

| 操作 | 社員 | IT担当者 | API・入力 / 成功後 |
| --- | --- | --- | --- |
| 詳細・コメント参照 | 自分だけ | 全件 | API-07 / API-11。コメント 0 件は「コメントはまだありません」 |
| 担当変更 | 表示しない | 未完了 | API-09：assignee_id / API-07 の version を expected_version として送信。成功詳細で version を置換 |
| 担当解除 | 表示しない | open のみ | API-09：assignee_id=null / expected_version |
| 状態変更 | 表示しない | 下記条件 | API-10：status / expected_version。成功詳細で状態・version・操作欄を更新 |
| コメント | 自分・未完了 | 全件・未完了 | API-12：body のみ。201 後本文を消去、API-07 と API-11 を再取得し、末尾ページを表示して投稿を通知 |

状態候補は **open → in_progress、in_progress → waiting_confirmation、waiting_confirmation → in_progress または completed**。担当者なしの対応開始は disabled と理由表示。停止担当者は API が 409 を返した時点で再割り当てを案内（画面へ is_active は返さない）。completed は両役割とも参照専用で、候補取得・変更欄・投稿フォームを表示しません。編集・削除・再開ボタンはありません。

IT は担当外でも変更できます。同じ依頼で担当・状態・投稿が同時送信されないよう画面内で共通 guard を使い、別タブ / 別利用者は API の version と親行ロックで処理します。409 後は最新詳細を再取得し、選択をリセット。「別の操作で更新されました」と通知し、利用者が確認後に選び直します。コメント下書きは未完了・同一利用者なら保持できますが、完了へ変わっていたら送信不可・手動破棄のみ。401 / 419 / 対象404 / 別アカウント時は下書きを消去します。

完了の UI 確認は IT の明示操作であり、社員の承認ボタン・確認コメント必須条件は追加しません。本文は React のテキストとして描画し、HTML / Markdown を実行しません。コメント再取得の失敗時は「投稿は成功しましたが表示更新に失敗しました」と、POST 失敗から区別します。

## 遷移の要約

```text
SCR-01 --ログイン成功--> SCR-02 --社員が登録へ--> SCR-03
SCR-03 --201 / 新ID--> SCR-04 --一覧へ--> SCR-02
SCR-02 --詳細リンク--> SCR-04
SCR-04 --担当・状態・コメント成功--> SCR-04（応答とGETで更新）
保護画面 --401 / 419 / ログアウト成功--> SCR-01
保護画面 --403 / 404--> 共通エラー領域 --戻る--> SCR-02
```

FR-09 の投入・公開終了・復元・削除画面は作りません。作成者が [DB の管理手順](database.md)を実行します。画面の認可・エラー・アクセシビリティと A / B / X / Y の実機操作は今後検証し、今回のレイアウトを動作確認済みとは扱いません。
